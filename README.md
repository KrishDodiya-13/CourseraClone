# CourseraClone

A modern, full-stack online learning platform inspired by modern EdTech platforms
such as Coursera.

CourseraClone is an independent educational project inspired by modern online
learning platforms. It is built with Next.js, TypeScript, Prisma and PostgreSQL.
Learners browse an original course catalogue, enrol, work through video and
reading lessons with progress that survives a reload or a lost connection, and
finish with a verifiable certificate. Instructors and administrators get their
own areas for authoring assessments and moderating the platform.

> Not affiliated with Coursera. See the [Disclaimer](#disclaimer).

## Features

Everything listed here is implemented in this repository.

### Accounts and access

- **User authentication** — email/password sign-up and sign-in with Argon2id
  password hashing, JWT sessions, email verification and password reset flows.
  Google OAuth is wired as an optional provider and stays disabled unless its
  credentials are supplied.
- **Role-based access** — learner, instructor and admin roles enforced on the
  server for every protected route and mutation, with suspended and deactivated
  accounts losing access immediately rather than at token expiry.
- **Profile** — editable profile with headline, bio, location and preferences.

### Discovery

- **Course discovery** — home page with featured, popular and newly published
  courses.
- **Course search** — full-text search across titles, subtitles and descriptions.
- **Course filtering** — filter by category, level, price band, rating, duration
  and tags, with sorting and pagination.
- **Course categories** — 17 categories, each with its own landing page and
  banner artwork.
- **Course detail pages** — curriculum tree, learning objectives, prerequisites,
  instructor profiles, ratings and reviews.
- **Wishlist** — save courses for later from any card or detail page.
- **Original course artwork** — every thumbnail and category banner is an
  original SVG generated by `scripts/build-thumbnails.mjs`; nothing is scraped or
  borrowed.

### Learning

- **Course enrollment** — free enrolment, or checkout for paid courses.
- **Learning dashboard** — in-progress courses, continue-where-you-left-off,
  activity, certificates and wishlist in one place.
- **Course progress tracking** — per-lesson and per-course completion, recorded
  server-side and mirrored locally so a dropped connection does not lose work.
- **Video learning** — a custom player with a lesson sidebar, keyboard support
  and throttled progress reporting.
- **Auto-resume playback** — a returning learner is offered their last position
  in a video lesson and resumes from it.
- **Reading lessons and resources** — article lessons with sanitised HTML, plus
  downloadable lesson resources.
- **Quizzes and assignments** — authored in the instructor studio, attempted by
  learners, auto-graded or manually reviewed.
- **Offline course content** — download a course for offline study; lesson text,
  metadata and images are stored in IndexedDB and the Cache Storage API, and
  progress made offline syncs back when the connection returns.
- **Course completion experience** — a completion celebration on finishing the
  last lesson.
- **Certificates** — issued on completion, with a public verification page so a
  certificate can be checked by serial without an account.

### Engagement

- **Learning streaks** — daily activity is logged and streaks are recomputed from
  that log rather than incremented in place.
- **Badges** — tiered achievement badges awarded from real activity.
- **Course reminders** — daily, weekly or custom study reminders with a
  time-of-day and timezone.
- **Notifications** — an in-app notification centre.

### Commerce

- **INR pricing** — prices are stored as integer minor units (paise) with an ISO
  currency code per row, and formatted through a single currency utility
  (`src/lib/currency.ts`) using the `en-IN` locale.
- **Checkout and orders** — order creation, coupon redemption, order history and
  receipts.
- **Payment providers** — a Stripe integration with signed webhook verification,
  plus a local sandbox provider so the full purchase flow can be exercised with
  no payment credentials configured.

### Instructor and admin

- **Instructor studio** — quiz authoring and submission review.
- **Admin platform** — dashboards for users, courses, categories, payments and
  reports, with every action written to an audit log.

### Platform

- **Responsive UI** — mobile-first layouts verified by Playwright across viewport
  sizes.
- **Theming** — light/dark appearance plus three selectable colour identities,
  applied before first paint so there is no flash.
- **PWA** — installable, with a service worker that precaches the app shell and
  falls back to an offline page. Authenticated responses are deliberately never
  cached.
- **Accessibility** — keyboard-navigable components built on Radix primitives,
  visible focus states and reduced-motion support.

## Getting Started

Requires **Node.js 20+**, **npm**, and a **PostgreSQL 16** database (Docker
Compose provides one).

```bash
# 1. clone
git clone https://github.com/KrishDodiya-13/CourseraClone.git
cd CourseraClone

# 2. install dependencies
npm install

# 3. configure environment variables
cp .env.example .env.local     # then fill in your own values

# 4. start PostgreSQL (optional — skip if you already run one)
docker compose up -d

# 5. create the schema and seed the catalogue
npm run db:migrate
npm run db:seed

# 6. start the development server
npm run dev
```

Open <http://localhost:3000>.

### Environment variables

Copy `.env.example` to `.env.local` and supply your own values — the example file
contains no real credentials, and `.env.local` is gitignored. Never commit real
secrets.

| Variable                                        | Required | Purpose                                                        |
| ----------------------------------------------- | -------- | -------------------------------------------------------------- |
| `DATABASE_URL`                                  | yes      | PostgreSQL connection string                                   |
| `AUTH_SECRET`                                   | yes      | Signs and encrypts the session JWT (`openssl rand -base64 32`) |
| `NEXT_PUBLIC_APP_URL`                           | no       | Canonical app origin                                           |
| `NEXT_PUBLIC_APP_NAME`                          | no       | Display name in the UI                                         |
| `POSTGRES_USER` / `_PASSWORD` / `_DB` / `_PORT` | no       | Read only by `docker-compose.yml`                              |
| `SEED_USER_PASSWORD`                            | no       | Shared password for seeded development accounts                |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`     | no       | Enables the Google provider; blank disables it                 |
| `AUTH_URL`                                      | no       | Pins callback URLs in production                               |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET`   | no       | Enables the Stripe provider                                    |
| `SANDBOX_WEBHOOK_SECRET`                        | no       | Signing key for the local sandbox provider                     |

## Testing

```bash
npm test              # Vitest unit tests, single run
npm run test:watch    # Vitest in watch mode
npm run test:e2e      # Playwright end-to-end suite
```

Unit tests live beside the code they cover (`*.test.ts`) and run in Vitest with
jsdom and Testing Library. End-to-end specs live in [`e2e/`](e2e) and run in
Playwright against a built app — smoke, authentication flow, responsive layout
and offline behaviour.

[`test/`](test) holds database-backed integration checks that exercise a real
PostgreSQL instance. They need `DATABASE_URL` configured and are run
individually:

```bash
npm run test:admin
npm run test:payments
npm run test:engagement
npm run test:assessment
npm run test:reset-flow
```

Static checks:

```bash
npm run typecheck
npm run lint
npm run format:check
```

## Database

PostgreSQL 16, accessed through **Prisma 7**. From Prisma 7 the connection URL
lives in [`prisma.config.ts`](prisma.config.ts) rather than in the schema, and
the runtime client is constructed with the `@prisma/adapter-pg` driver adapter in
[`src/server/db.ts`](src/server/db.ts). The generated client is emitted to
`src/generated/prisma`.

The schema in [`prisma/schema.prisma`](prisma/schema.prisma) covers users and
profiles, auth tokens, the catalogue (categories, tags, courses, sections,
lessons, resources), enrolment and progress, assessments (quizzes, attempts,
assignments, submissions), reviews, commerce (orders, payments, coupons,
payouts), certificates, engagement (notifications, reminders, activity, streaks,
badges) and an audit log — applied through 15 migrations.

Local database via Docker Compose:

```bash
docker compose up -d
```

It publishes on host port **5434** by default (configurable with
`POSTGRES_PORT`), because 5432 and 5433 are commonly taken by locally installed
PostgreSQL servers.

### Seeding

`npm run db:seed` populates a realistic development dataset: staff, instructor
and learner accounts, 17 categories, 80 tags, 20 instructors and 158 original
courses with full section and lesson trees, plus enrolments, progress, reviews
and certificates.

The seed is **deterministic** — it derives every value from a seeded PRNG rather
than `Math.random()`, and upserts by slug, so running it repeatedly produces the
same catalogue instead of duplicates. It refuses to run against
`NODE_ENV=production`, and contains no committed credentials: every seeded
account shares one throwaway password read from `SEED_USER_PASSWORD` and hashed
with Argon2id at run time.

## Deployment

The application deploys to **Vercel** as a standard Next.js App Router project.

A deployment requires two things that local development does not: its own
production environment variables, set in the Vercel project settings rather than
in a file, and a hosted PostgreSQL database. The local Docker Compose database is
for development only.

1. Push the repository to GitHub and import it into Vercel.
2. Provision a PostgreSQL database (Vercel Postgres, Neon, Supabase or any other
   managed provider) and set `DATABASE_URL`.
3. Set `AUTH_SECRET`, and `AUTH_URL` / `NEXT_PUBLIC_APP_URL` to the deployed
   origin. Add the Stripe and Google variables only if those integrations are
   wanted.
4. Run `npm run db:deploy` against the production database to apply migrations.
   Do not run the development seed there.

`prisma generate` runs via `postinstall`, so no extra build step is required.
Security headers (CSP, HSTS, `X-Frame-Options`, `nosniff`, Referrer-Policy,
Permissions-Policy) are configured in [`next.config.ts`](next.config.ts).
